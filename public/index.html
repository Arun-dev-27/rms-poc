Load all data: MSSQL → Redis

Wipes Redis records, then streams all rows from MSSQL into Redis (MSET, 5,000 per batch). Usually 35–53 s.

Delete all Redis data

Removes every record from Redis, which simulates Redis data being lost. MSSQL is not touched.

Take snapshot

Saves all Redis records to a gzip file, plus the MSSQL change version. Also runs automatically every 15 min.

Restore: Snapshot → Redis

Loads the latest snapshot into Redis, then applies every MSSQL change made after it. Usually 11–19 s.

Reconcile with MSSQL

Copies changes made directly in MSSQL (outside this API) into Redis. Runs every minute automatically.

Re-import from stage

Replaces the docker MSSQL table with a fresh copy from stage (read-only), then reloads Redis. About 3 minutes.

Distributed 1 lakh request test

Ticket-booking style test over every running API instance. Requests on the same record wait their turn in line, so every request succeeds; a duplicate request is applied once; a cancel cancels the request being processed, everyone waiting in line and every later request; reads always work; MSSQL = Redis at the end. The test changes the Post column of ~12,000 records and restores the original values at the end.
